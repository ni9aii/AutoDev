# Plan ↔ Execute Bridge

This reference explains how AutoDev's aggregation phase output (the
`plan`) connects to the execution phase and how the standalone
`plan` skill enhances it.

## Two kinds of plan

AutoDev produces two different artifacts, both called "plan":

| Artifact | Generated by | Purpose | When |
|----------|-------------|---------|------|
| **Aggregator plan** | `review-aggregator` (or manual) | Operational fix list from review findings | After `review` phase |
| **Implementation plan** | `plan` skill (human-authored) | Design-level implementation breakdown with tasks, TDD, verification | Before `execute` phase |

The aggregator plan is a **starting point**, not a replacement for the
`plan` skill when the work is non-trivial.

## Flow: aggregator plan → plan skill → execute

```text
review → aggregate → (optional: use plan skill to flesh out) → execute → verify
```

### 1. Aggregator produces the raw plan

```bash
review-aggregator --dev-notes --project <name>
```

Output: `plans/<timestamp>-plan.md` with "🔴 Do Now" and "🟡 Defer".

### 2. For simple fixes (≤2 files, ≤20 lines per fix)

Skip explicit planning. Execute directly:

- Read the file with `read_file`
- Apply fix with `patch` or `write_file`
- Commit per fix

### 3. For complex fixes

Use the `plan` skill to decompose before executing:

1. Copy each "Do Now" finding as the seed for a plan.
2. Run `/plan` (load the `plan` skill) to produce a `SubagentDrivenDevelopment`-compatible task list:
   - Bite-sized tasks (2-5 min each)
   - Exact file paths
   - Complete test-first code examples
   - TDD cycle per task
3. Execute the plan with `subagent-driven-development`.

## Example: bridging a CRITICAL finding

Aggregator output (from plan):

```markdown
### Fix 1: SQL injection in db.rs query builder
**Source:** code Reviewer
**Severity:** CRITICAL
**File:** `src/db.rs`
**Line:** 42
**Description:** User-supplied `name` concatenated into SQL.
**Action:** _To be filled by implementer_
```

Converted into plan-skill input:

```markdown
# Fix SQL Injection in db.rs Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement
> this plan task-by-task.
>
> **Goal:** Replace string concatenation with parameterized queries.
>
> **Architecture:** Extract query-building into a helper that uses
> SQL placeholders; validate input length before passing to DB.
>
> **Tech Stack:** Rust, sqlx (or whatever the project uses)
>
> ---
>
> ### Task 1: Write failing test for injection attempt
>
> ... (TDD cycle as per plan skill)
>
> ### Task 2: Implement parameterized query helper
>
> ... (TDD cycle)
```
